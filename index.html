05 / TROUBLESHOOTING IN PRACTICE

Real-world technical investigations.

Examples of how I approach production issues, compare evidence, investigate root causes and collaborate on resolutions.

CASE 01 / API GATEWAY

HTTP 429 despite remaining API quota

An API vendor received intermittent rate-limit errors even though their available quota had not been exhausted.

Explore investigation →

Investigation: Compared successful and failed requests, checked gateway logs and inspected remaining-quota and rate-limit headers.

Finding: Identified a gateway-level Spike Arrest configuration of 200 ms, equivalent to approximately five requests per second. This was throttling requests independently of the remaining quota.

Next step: The findings could be shared with the gateway team to review the configuration and error messaging.

Tools: Gravitee, gateway logs, Postman.

CASE 02 / BACKEND PERFORMANCE

API timeout affecting a specific property

API requests timed out for one property while requests for other properties continued to work.

Explore investigation →

Investigation: Compared affected and successful properties, examined gateway logs, traced application logs and investigated transaction execution time.

Finding: The backend transaction for the affected property was taking approximately 20 minutes. I investigated data volume, execution logic and property-specific configuration.

Collaboration: Shared the investigation findings with Engineering for further analysis.

Tools: Gravitee, New Relic, application logs, SQL, Postman.

CASE 03 / PERFORMANCE ANALYSIS

Investigating API timeouts with lower memory usage

A timed-out request showed lower memory consumption than a successful request, making the performance issue less obvious.

Explore investigation →

Evidence comparison:

Database duration: 528 ms for the timed-out request versus 187 ms for the successful request.

Memory consumed: 17 MB versus 48 MB.

PHP peak memory: 37 MB versus 110 MB.

Finding: The timed-out request had approximately 2.8 times the database duration, despite using less memory. The database timing alone did not establish the complete cause of the timeout.

Further investigation: Total request duration, downstream calls, application processing and gateway timeout configuration need to be considered.

Tools: Gateway logs, New Relic, SQL, application logs.

PerformanceDatabase DurationNew Relic
CASE 04 / CODE-LEVEL INVESTIGATION

HTTP 500 caused by unexpected null handling

An API returned an internal server error when a particular field was empty instead of containing a value.

Explore investigation →

Investigation: Reproduced the issue using Postman, checked gateway and application logs, and traced the relevant code flow using Cursor IDE.

Finding: A variable or function returned null where the application expected a default value of zero.

Code contribution: Implemented handling to default the missing value to zero, then tested both populated and missing-value scenarios.

Outcome: Raised a pull request for Engineering review. This describes the submitted fix, not a confirmed merge or production deployment.

Tools: Cursor IDE, Postman, application logs, Git, Jira.
