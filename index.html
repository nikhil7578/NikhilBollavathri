01. API returning 429 despite available quota

GATEWAY · RATE LIMITING · SPIKE ARREST

Problem

A vendor reported intermittent HTTP 429 Too Many Requests responses even though the customer still had API quota remaining.

Troubleshooting

  • Checked gateway logs to identify the exact error and rejection point.
  • Verified the customer's remaining quota and rate-limit headers.
  • Compared successful and failed requests to identify patterns.
  • Investigated the gateway's rate-limiting configuration.
  • Identified a gateway-level Spike Arrest configuration of 200 milliseconds, allowing approximately five requests per second.
  • Distinguished normal quota exhaustion from gateway-level burst throttling.

Resolution & Outcome

Identified that requests were being rejected by gateway-level throttling rather than customer quota exhaustion. This explained why customers received 429 responses despite having remaining quota. The findings provided evidence for the gateway team to review throttling configuration and customer-facing error messaging.

02. API timeout caused by long-running backend transaction

TIMEOUT · BACKEND TRANSACTION · LOG ANALYSIS

Problem

A vendor reported API timeouts for a particular property, while requests for other properties were working successfully. Investigation identified a backend transaction taking approximately 20 minutes, exceeding the expected processing time.

Troubleshooting

  • Checked gateway logs to confirm the timeout.
  • Identified the affected property and compared its requests with successful property requests.
  • Traced the request through application logs.
  • Investigated the backend transaction and its execution time.
  • Checked whether the issue was related to data volume, processing logic, or a specific property configuration.
  • Shared the findings with Engineering for deeper investigation.

Investigation Outcome

Isolated a long-running backend transaction of approximately 20 minutes as a key finding associated with the affected property. The evidence helped narrow the investigation toward backend processing rather than treating the issue as a general API or vendor connectivity failure. Further remediation details were not included in this case study.
